3ข้อมูลไหลอย่างไร

ลำดับการทำงานของทุกครั้งที่คุณกดบันทึกในระบบ

01
ผู้ใช้กดบันทึก

ฟอร์มส่ง data → JavaScript คำนวณ (auto-compose, validation, ID gen, timeline auto) → เก็บลง DB.*

02
save() ทำงาน

JSON.stringify ทั้ง DB{} → เขียน localStorage[shelteros_crm_v2] · หากเต็ม → alert ดัง (ไม่เงียบ) · autoBackup snapshot

03
Push ขึ้น cloud ทันที

POST /rest/v1/crm_state {id:1, doc, updated_at} ผ่าน anon key · resolution=merge-duplicates · ไม่รอ debounce

04
Broadcast ให้ tab อื่น

BroadcastChannel post {type:"saved"} → tab อื่นในเครื่องเดียวกัน pull cloud ทันที (กัน overwrite)

05
Device อื่น sync

Poll ทุก 20 วิ · GET ?id=eq.1 · เทียบ updated_at ผ่าน epoch (Date.parse) · ใหม่กว่า 500ms = pull applyCloudDoc

06
รูปแยกเก็บที่ Storage

Photo upload ไม่เก็บใน state blob · ไปอยู่ที่ property-images/{JJxxx}/{file} · state เก็บแค่ URL string

4Auth และสิทธิ์เข้าถึง

ระบบเป็น single-user · ปัจจุบันไม่ได้ใช้ Supabase Auth · ใช้ PIN local + anon key เข้าถึง Supabase

ปัจจุบัน: ใครที่มี URL crm.shelterlivingestate.tech + PIN ที่คุณตั้ง → เข้าใช้ได้ · anon key ของ Supabase ฝังใน HTML (ทุกคนที่โหลดหน้าเห็น key) · RLS ควบคุมสิทธิ์อ่าน/เขียน crm_state และ Storage bucket · Storage policies scoped bucket_id='property-images'

ถ้าจะเข้มกว่านี้ (Phase ถัดไป): ต้องเพิ่ม Supabase Auth (email/password) · เปลี่ยน RLS ให้ตรวจ authenticated role · CRM ต้องเพิ่ม sign-in flow · ไม่เร่งขณะเป็น single-user

5ถ้าข้อมูลหาย · กู้คืนอย่างไร

4 ทางเลือกเรียงตามความง่าย · เริ่มจากทางที่เร็วที่สุด

  1. คลาวด์ยังอยู่ → เมนู จัดการข้อมูล → กด ⬇ ดึงจากคลาวด์ → confirm → เสร็จใน 3 วิ
  2. Local backup ยังอยู่ → เมนู จัดการข้อมูล → กู้คืน 1 ใน 3 snapshot รายวัน (เก็บใน localStorage เดิม)
  3. มีไฟล์ Export → เมนู จัดการข้อมูล → กด Import JSON → เลือกไฟล์ล่าสุด → confirm
  4. รูปหายจาก state แต่ยังใน Storage → รูปยังเปิดจาก URL ได้ · re-attach path property-images/{JJxxx}/ ในทรัพย์ที่ต้องการ

6Rollback โค้ด (แยกจากข้อมูล)

โค้ดกับข้อมูลอยู่คนละที่ · rollback โค้ดจึงไม่แตะข้อมูล

วิธี: ที่ GitHub repo → เข้า commit history → เลือก commit ก่อนหน้า → กด "revert" หรือ terminal git revert <hash> && git push → Cloudflare deploy อัตโนมัติภายใน ~1 นาที

ผลกระทบ: โค้ดกลับไป version เดิม · ข้อมูลใน Supabase / localStorage / Storage ทั้งหมดไม่เปลี่ยน · ต่อเนื่องได้ทันที
